# scheduled-publishing Specification

## Purpose
版一覧データを定期的または手動で最新化し、閲覧ページを GitHub Pages で公開し続けることで、PC と iPhone のどちらからでも最新の更新日一覧を見られるようにする。

## Requirements

### Requirement: 定期更新（イベント駆動）
毎週木曜日と日曜日の 06:00 JST になったとき、更新ワークフローは版一覧の取得を開始すること。

#### Scenario: 木曜の朝に取得が始まる
- **WHEN** 木曜日の 06:00 JST になったとき
- **THEN** 更新ワークフローの実行が開始され、版一覧の取得が行われること

### Requirement: 手動更新（イベント駆動）
リポジトリの管理者が GitHub 上で更新ワークフローを手動実行したとき、更新ワークフローは版一覧の取得を開始すること。

#### Scenario: 手動で取得する
- **WHEN** 管理者が GitHub の Actions 画面から更新ワークフローを手動実行したとき
- **THEN** 版一覧の取得が行われること

### Requirement: 差分がある場合のコミットと公開（イベント駆動）
取得の結果データファイルに差分が生じたとき、更新ワークフローはデータファイルを `main` ブランチにコミットし、そのコミット時点の閲覧ページを GitHub Pages に公開すること。

#### Scenario: 新しい版が公開される
- **GIVEN** 公開中の閲覧ページに 25 版が表示されている
- **AND** Qiita 上に新しい版が 1 つ追加されている
- **WHEN** 更新ワークフローが実行されたとき
- **THEN** `main` ブランチにデータファイルを更新するコミットが 1 つ追加されること
- **AND** 公開中の閲覧ページに 26 版が表示されること

### Requirement: 差分がない場合の無コミット（イベント駆動）
取得の結果データファイルに差分が生じなかったとき、更新ワークフローはコミットを作成しないこと。

#### Scenario: 新しい版がない
- **GIVEN** Qiita 上に未取得の版がない
- **WHEN** 更新ワークフローが実行されたとき
- **THEN** `main` ブランチにコミットが追加されないこと

### Requirement: main への push 時の公開（イベント駆動）
`main` ブランチに push されたとき、更新ワークフローは版一覧を取得せずに、push 後の閲覧ページを GitHub Pages に公開すること。

#### Scenario: 画面の修正が公開される
- **WHEN** 開発者が閲覧ページを修正したコミットを `main` に push したとき
- **THEN** 修正後の閲覧ページが GitHub Pages で公開されること

### Requirement: 取得失敗時の扱い（望ましくない事象）
版一覧の取得が失敗した場合、更新ワークフローは実行を失敗として終了し、コミットの作成と GitHub Pages への公開を行わないこと。

#### Scenario: Qiita の構造が変わっていた
- **GIVEN** 公開中の閲覧ページに 25 版が表示されている
- **AND** 取得スクリプトが 0 以外の終了コードで終了する
- **WHEN** 更新ワークフローが実行されたとき
- **THEN** ワークフローの実行結果が失敗になること
- **AND** 公開中の閲覧ページに 25 版が表示されたままであること
