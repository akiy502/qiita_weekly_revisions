# revision-collection Specification

## Purpose
Qiita「週間トレンド記事一覧」の revisions ページから版の一覧（更新日時と版 ID）を取得し、閲覧ページが読み込めるデータファイルとして差分で蓄積する。

## Requirements

### Requirement: 差分取得（イベント駆動）
取得したページにデータファイルに保存済みの版が 1 件以上含まれていたとき、取得スクリプトはそのページの版のうち、データファイルにない版だけをデータファイルに追加すること。

#### Scenario: 新しい版だけが追加される
- **GIVEN** データファイルに 556 版が保存されている
- **AND** revisions ページの 10 件のうち、先頭 2 件が未保存で、残り 8 件が保存済みである
- **WHEN** 取得スクリプトを実行したとき
- **THEN** データファイルの版数が 558 になること

### Requirement: 差分がない場合の無変更（イベント駆動）
取得した版がすべてデータファイルに存在していたとき、取得スクリプトはデータファイルの内容をバイト単位で変更しないこと。

#### Scenario: 新しい版がないときはファイルが変わらない
- **GIVEN** データファイルに revisions ページ上の全版が保存されている
- **WHEN** 取得スクリプトを実行したとき
- **THEN** データファイルの内容が実行前と同一であること

### Requirement: データファイルの並び順と一意性（ユビキタス）
取得スクリプトと取り込みスクリプトは、データファイル内の版を更新日時の降順に並べ、同じ版を 2 回以上含めないこと。

#### Scenario: 降順かつ重複なしで保存される
- **GIVEN** データファイルに 2026-10-10 までの 556 版が保存されている
- **AND** 取り込むデータに、保存済みの 556 版と、それより新しい 2 版が含まれる
- **WHEN** 取り込みスクリプトを実行したとき
- **THEN** データファイルの版数が 558 になること
- **AND** データファイルの先頭の版が最も新しい更新日時を持つこと

### Requirement: 版一覧を読み取れない場合の中断（望ましくない事象）
取得したページから版一覧データを読み取れない場合、取得スクリプトは 0 以外の終了コードで終了し、データファイルを変更しないこと。

#### Scenario: ページ構造が変わっていた
- **GIVEN** データファイルに 25 版が保存されている
- **AND** revisions ページに版一覧データが埋め込まれていない
- **WHEN** 取得スクリプトを実行したとき
- **THEN** 取得スクリプトの終了コードが 0 以外であること
- **AND** データファイルの内容が実行前と同一であること

### Requirement: 通信失敗時の中断（望ましくない事象）
ページ取得の HTTP ステータスが 200 以外であるか通信に失敗した場合、取得スクリプトは 0 以外の終了コードで終了し、データファイルを変更しないこと。

#### Scenario: サーバーエラーが返った
- **GIVEN** データファイルに 25 版が保存されている
- **AND** revisions ページが HTTP 503 を返す
- **WHEN** 取得スクリプトを実行したとき
- **THEN** 取得スクリプトの終了コードが 0 以外であること
- **AND** データファイルの内容が実行前と同一であること

### Requirement: 1 ページ目の取得（イベント駆動）
取得スクリプトが実行されたとき、取得スクリプトは `https://qiita.com/Qiita/items/b5c1550c969776b65b9b/revisions`（クエリパラメータなし）を 1 回だけ取得し、そのページに含まれる版の更新日時と版 ID を読み取ること。

#### Scenario: 1 回のリクエストで終わる
- **GIVEN** データファイルに 556 版が保存されている
- **WHEN** 取得スクリプトを実行したとき
- **THEN** 取得スクリプトが qiita.com に送るリクエストは、`https://qiita.com/Qiita/items/b5c1550c969776b65b9b/revisions` への 1 回だけであること

### Requirement: データファイルがない場合の中断（望ましくない事象）
データファイルが存在しない場合、取得スクリプトは qiita.com にリクエストを送らずに 0 以外の終了コードで終了し、過去分の取り込み手順を案内するメッセージを標準エラー出力に出すこと。

#### Scenario: 初回に取得スクリプトを実行した
- **GIVEN** データファイルが存在しない
- **WHEN** 取得スクリプトを実行したとき
- **THEN** 取得スクリプトの終了コードが 0 以外であること
- **AND** qiita.com へのリクエストが 0 回であること
- **AND** 標準エラー出力に過去分の取り込み手順の案内が含まれること

### Requirement: 差分を埋められない場合の中断（望ましくない事象）
取得したページにデータファイルに保存済みの版が 1 件も含まれない場合、取得スクリプトは 0 以外の終了コードで終了し、データファイルを変更せず、過去分の取り込み手順を案内するメッセージを標準エラー出力に出すこと。

#### Scenario: 前回の取得から版が 10 件を超えて増えていた
- **GIVEN** データファイルに 556 版が保存されている
- **AND** revisions ページの 10 件がすべて未保存の版である
- **WHEN** 取得スクリプトを実行したとき
- **THEN** 取得スクリプトの終了コードが 0 以外であること
- **AND** データファイルの内容が実行前と同一であること
- **AND** 標準エラー出力に過去分の取り込み手順の案内が含まれること

### Requirement: ページ位置の照合（望ましくない事象）
取得したページの版一覧データが示す現在のページ番号が 1 でない場合、取得スクリプトは 0 以外の終了コードで終了し、データファイルを変更しないこと。

#### Scenario: 1 ページ目以外が返った
- **GIVEN** データファイルに 556 版が保存されている
- **AND** revisions ページの版一覧データの現在のページ番号が 2 である
- **WHEN** 取得スクリプトを実行したとき
- **THEN** 取得スクリプトの終了コードが 0 以外であること
- **AND** データファイルの内容が実行前と同一であること

### Requirement: 過去分の取り込み（イベント駆動）
利用者が GraphQL `GetArticleRevisions` の応答を保存した JSON ファイルを指定して取り込みスクリプトを実行したとき、取り込みスクリプトはそのファイルに含まれる全版をデータファイルにマージすること。

#### Scenario: 保存した応答から全版を取り込む
- **GIVEN** データファイルが存在しない
- **AND** 指定した JSON ファイルが、556 版を含み最終ページであることを示す応答である
- **WHEN** 取り込みスクリプトを実行したとき
- **THEN** データファイルに 556 版が保存されること

#### Scenario: 既存のデータに追加で取り込む
- **GIVEN** データファイルに 556 版が保存されている
- **AND** 指定した JSON ファイルに、保存済みの版と未保存の 12 版が含まれ、最終ページであることを示す
- **WHEN** 取り込みスクリプトを実行したとき
- **THEN** データファイルの版数が 568 になること

### Requirement: 取り込みデータの完全性の確認（望ましくない事象）
指定した JSON ファイルの応答が、1 ページ目から最終ページまでが連続して揃っていることを示さない場合、取り込みスクリプトは 0 以外の終了コードで終了し、データファイルを変更しないこと。

#### Scenario: 最終ページまで揃っていない
- **GIVEN** データファイルに 556 版が保存されている
- **AND** 指定した JSON ファイルの応答が 1 ページ目だけで、最終ページではないことを示す
- **WHEN** 取り込みスクリプトを実行したとき
- **THEN** 取り込みスクリプトの終了コードが 0 以外であること
- **AND** データファイルの内容が実行前と同一であること

### Requirement: 取り込みデータの形式不正の拒否（望ましくない事象）
指定した JSON ファイルを GraphQL `GetArticleRevisions` の応答として解釈できない場合、取り込みスクリプトは 0 以外の終了コードで終了し、データファイルを変更しないこと。

#### Scenario: エラー応答を指定した
- **GIVEN** データファイルに 556 版が保存されている
- **AND** 指定した JSON ファイルの内容が `{"errors":[{"message":"CSRF token is invalid"}]}` である
- **WHEN** 取り込みスクリプトを実行したとき
- **THEN** 取り込みスクリプトの終了コードが 0 以外であること
- **AND** データファイルの内容が実行前と同一であること
